# Week 3 Slide Redesign Pipeline

## Goal

- Implement a small, testable pipeline for `scripts/generate_week_3_presentation.py` that:
  - classifies each generated Week 3 slide into `cover`, `comic`, `chart`, or `divider`
  - applies a different image-edit prompt template per slide kind
  - preserves the current deterministic local rendering path as a fallback
  - emits a redesigned PDF and flattened PPTX from the AI-edited slide images
  - supports both OpenAI and Gemini providers behind the same internal interface
  - manages provider selection and redesign behavior through environment variables
  - supports dry runs, caching, and review artifacts so API usage is controllable

## Current State

- The Week 3 deck is generated by `scripts/generate_week_3_presentation.py`.
- The script currently:
  - renders every slide as a `PIL.Image`
  - saves a PDF with `save_pdf()`
  - saves a flattened PPTX with `save_pptx()` by embedding each PNG as a full-slide image
- `build_slides()` returns `list[Image.Image]` only. No slide metadata, classification, prompt context, or intermediate manifest exists.
- Slide intent is implicit in the builder calls inside `build_slides()`:
  - `cover_slide()` for the opening slide
  - `add_dialogue_slide()` for comic / dialogue slides
  - `code_sleep_repeat_slide()` for divider slides
  - all remaining PIL + matplotlib layouts for chart / concept slides
- The current script extracts mascots and the cover photo from `big_data_course_content/presentations/week_2.pdf` via hard-coded `ASSET_XREFS`, which is brittle if the source PDF changes.
- `week_3.pptx` is currently a flattened deck. Each slide is a single full-slide image, not editable PowerPoint shapes.
- `pyproject.toml` already defines `ruff`, `mypy`, and `pytest` configuration, but the Week 3 generator itself uses undeclared presentation-specific libraries such as `fitz`, `matplotlib`, `numpy`, `Pillow`, and `python-pptx`.
- The repo’s actual local runners are:
  - `.venv/bin/pytest`
  - `.venv/bin/ruff`
  - `.venv/bin/mypy`

## Findings

- The cleanest place to classify slides is not after rendering from the PDF or PPTX. It is inside `build_slides()`, because the script already knows which builder produced each slide.
- `build_slides()` currently produces a stable semantic grouping for the Week 3 deck:
  - `cover`: 1 slide
  - `comic`: 8 dialogue slides
  - `divider`: 2 `CODE / SLEEP / REPEAT` slides
  - `chart`: all remaining instructional slides with plots, equations, callout boxes, and takeaways
- Because the final PPTX is flattened anyway, an image-editing pipeline is compatible with the existing export approach. No editable PowerPoint reconstruction is required to reach the stated objective.
- The highest implementation risk is text fidelity on chart-heavy slides. A prompt pipeline can improve polish, but image generation models can still distort labels, equations, and small annotations.
- A dry-run mode, cache manifest, and review contact sheet are necessary if the redesign step will use a paid external API.
- OpenAI and Gemini are both viable for image editing, so the provider layer should be explicit from the start rather than retrofitted later.
- If provider selection is environment-driven, the script can stay stable while local/CI execution chooses `openai`, `gemini`, or `none` without changing command invocations.
- The current hard-coded `ASSET_XREFS` are unrelated to slide classification, but they are a reliability risk for any larger redesign workflow because they couple Week 3 generation to specific image object IDs inside `week_2.pdf`.

## Scope

### In scope

- Refactor the Week 3 generator to expose slide metadata alongside rendered slide images.
- Introduce explicit slide-kind classification for `cover`, `comic`, `chart`, and `divider`.
- Define versioned prompt templates and shared style constraints for each slide kind.
- Add an AI redesign stage that can:
  - accept rendered slide images
  - build prompts from slide metadata + style profile
  - call either the OpenAI image-edit API or the Gemini image-edit API
  - cache outputs and skip re-generation when inputs are unchanged
- Add environment-variable-driven controls for provider, model, cache/work directory, dry run, and selective redesign.
- Keep CLI arguments focused on file inputs/outputs and generation entry points rather than provider policy.
- Emit human-review artifacts such as:
  - prompt manifest
  - per-slide classification manifest
  - before/after contact sheet
- Keep the existing local-only rendering path functional when redesign is disabled.
- Add tests for classification, prompt compilation, cache-key stability, and dry-run behavior.
- Add docs explaining the Week 3 redesign flow and required environment variables.

### Out of scope

- Rebuilding the Week 3 deck into editable PowerPoint text boxes and charts.
- Applying the redesign pipeline to all course decks.
- Fine-tuning or training a custom image model.
- Fully automating semantic QA of AI-edited text and equations without human review.
- Replacing the broader course authoring workflow outside `scripts/generate_week_3_presentation.py`.

## Data and Contract Changes

- New internal slide contract:
  - replace anonymous `Image.Image` list elements with structured slide records that include:
    - `index`
    - `kind`
    - `title`
    - `speaker_text` or summary context when relevant
    - `base_image`
    - optional `notes` or prompt hints
- New style profile contract:
  - a JSON file that defines:
    - global style direction
    - per-kind prompt prefix and constraints
    - provider-specific model defaults
    - optional output resolution or aspect-ratio settings
- New environment contract. Recommended variables:
  - `WEEK3_REDESIGN_PROVIDER=openai|gemini|none`
  - `WEEK3_REDESIGN_MODEL=<provider-specific-model>`
  - `WEEK3_REDESIGN_ENABLED=1|0`
  - `WEEK3_REDESIGN_DRY_RUN=1|0`
  - `WEEK3_REDESIGN_CACHE_DIR=<path>`
  - `WEEK3_REDESIGN_WORK_DIR=<path>`
  - `WEEK3_REDESIGN_ONLY_KIND=cover|comic|chart|divider`
  - `WEEK3_REDESIGN_PROFILE=<path>`
  - `OPENAI_API_KEY=<secret>` for the OpenAI adapter
  - `GEMINI_API_KEY=<secret>` for the Gemini adapter
- New CLI contract for `scripts/generate_week_3_presentation.py`:
  - keep `--output`, `--output-pptx`, and `--source-pdf`
  - optionally add a minimal `--redesign-profile` override only if needed for local experimentation
  - do not require CLI flags to switch providers or models; env vars are authoritative
- Output artifact contract:
  - a manifest JSON in the redesign work directory containing slide classification, prompts, hashes, and output image paths
  - provider/model information resolved from env vars and persisted in the manifest
  - a before/after contact sheet for manual approval

## Implementation Steps

1. Refactor the generator around explicit slide metadata.
   - Introduce `SlideKind` as an enum or literal set: `cover`, `comic`, `chart`, `divider`.
   - Introduce a `SlideSpec` or `RenderedSlide` dataclass in a new `src` module.
   - Change `build_slides()` so each slide builder returns a structured object rather than only a raw `Image.Image`.
   - Preserve the current rendering order and local rendering output during this refactor.

2. Stabilize the base assets the Week 3 script depends on.
   - Extract the current PDF-derived assets into `big_data_course_content/presentations/assets/week_3/`.
   - Replace `extract_assets()` + `ASSET_XREFS` usage with explicit file loads, or keep a temporary compatibility path while moving callers to the stable assets.
   - Keep asset file names aligned with the existing semantic keys: `cover_photo`, `logo`, `llama`, `boar`, `robot`.

3. Build the classification and prompt-assembly layer.
   - Encode slide kind directly at creation time:
     - `cover_slide()` -> `cover`
     - `add_dialogue_slide()` -> `comic`
     - `code_sleep_repeat_slide()` -> `divider`
     - remaining instructional slides -> `chart`
   - Populate prompt context for each slide from existing titles, subtitles, and dialogue copy inside `build_slides()`.
   - Create `week_3_redesign_profile.json` with:
     - shared direction such as “Andean high-dimensional editorial comic”
     - per-kind prompt templates
     - negative prompts that forbid text corruption, added logos, watermarks, or layout destruction
     - provider-specific default models for OpenAI and Gemini

4. Add the provider abstraction and both adapters.
   - Introduce a provider-agnostic editing interface in `src/upc_datasets/week_3_presentation_ai.py`.
   - Implement `src/upc_datasets/week_3_presentation_openai.py` for the OpenAI image-edit flow.
   - Implement `src/upc_datasets/week_3_presentation_gemini.py` for the Gemini image-edit flow.
   - Resolve provider choice from `WEEK3_REDESIGN_PROVIDER`.
   - Resolve credentials from `OPENAI_API_KEY` or `GEMINI_API_KEY` depending on the selected provider.
   - Support provider mocking in tests and a clean failure mode when the required env vars are absent.
   - Return decoded `PIL.Image` objects plus response metadata needed for the manifest.

5. Add caching, dry-run, and review artifacts.
   - Compute a deterministic cache key from:
     - input image bytes
     - slide kind
     - rendered prompt
     - provider/model name
     - style profile version
   - Store generated slide PNGs and manifest JSON in a work directory.
   - Read cache/work directory settings from env vars so the command line stays stable across providers.
   - Implement dry-run behavior driven by `WEEK3_REDESIGN_DRY_RUN` to produce:
     - base rendered slide PNGs
     - classification manifest
     - prompt manifest
     - no network calls
   - Implement a contact-sheet generator that shows original and redesigned variants side by side for manual review.

6. Reconnect the redesigned assets to export.
   - After redesign, feed the edited slide images into the existing `save_pdf()` and `save_pptx()` functions.
   - Keep the flattened PPTX export; this is acceptable because the redesign pipeline operates on slide images.
   - Ensure a fully local path still exists when redesign is disabled or when API calls fail.

7. Expose the workflow in the CLI and docs.
   - Keep `parse_args()` minimal and centered on file inputs/outputs.
   - Load redesign configuration from env vars in a dedicated config loader.
   - Document examples in `runbooks/09-presentation-redesign.md` for:
     - local render only
     - dry run with prompt generation using `WEEK3_REDESIGN_DRY_RUN=1`
     - redesign of all slides with `WEEK3_REDESIGN_PROVIDER=openai`
     - redesign of all slides with `WEEK3_REDESIGN_PROVIDER=gemini`
     - redesign of one slide kind only for iteration via `WEEK3_REDESIGN_ONLY_KIND`
     - regeneration from cache

8. Add test coverage and guardrails.
   - Unit-test classification to ensure slide kinds remain stable when the slide order changes only intentionally.
   - Unit-test prompt generation so each kind gets the correct template and injected context.
   - Unit-test cache-key generation and manifest serialization.
   - Mock provider calls in integration tests so CI or local validation never requires network access.
   - Add one integration check that the final script still emits outputs when redesign is disabled.

## Risks and Mitigations

- AI model alters chart labels, equations, or small text -> keep chart prompts conservative, generate review contact sheets, and require human approval before promoting redesigned outputs.
- Prompt templates overfit to Week 3’s current slide order -> derive kind and context from the slide builder call sites, not hard-coded slide indexes alone.
- API cost grows during iteration -> support `--redesign-dry-run`, per-kind filtering, and deterministic cache reuse.
- Provider SDK or credentials are unavailable locally -> preserve a no-network path, resolve provider from env vars, and isolate provider code so imports and failures do not break the base render path.
- OpenAI and Gemini return different output formats or capabilities -> normalize responses through a shared provider interface and persist provider metadata in the manifest for debugging.
- The current PDF xref asset extraction changes unexpectedly -> replace xref-dependent assets with committed PNGs under `big_data_course_content/presentations/assets/week_3/`.
- The new orchestration logic becomes hard to test if left inside the script -> move slide metadata, prompt building, and provider code into `src` modules and keep the script thin.
