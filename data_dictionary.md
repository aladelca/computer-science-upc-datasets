# PachaMix Data Dictionary

This document describes the processed datasets generated by the toolkit in this workspace.

As of `2026-03-16`, the currently generated real outputs are:

- `data/processed/pachamix_audio_core.parquet`
- `data/processed/pachamix_lyrics_long.parquet`

The playlist and graph outputs are supported by the codebase but require a staged playlist-behavior source such as `Playlist2vec` or `MPD`.

## Source Lineage

### Audio Core

- Source: `FMA`
- Raw inputs:
  - `data/raw/fma/tracks.csv`
  - `data/raw/fma/features.csv`
- Join key: `track_id`
- Grain: `one row per FMA track`

### Lyrics Long

- Source: `musiXmatch/MSD`
- Raw inputs:
  - `data/raw/musixmatch_msd/mxm_dataset_train.txt`
  - `data/raw/musixmatch_msd/mxm_dataset_test.txt`
- Optional metadata enrichment:
  - `data/raw/msd/track_metadata.db`
- Join key:
  - `musiXmatch/MSD` lyrics `msd_track_id`
  - MSD metadata `songs.track_id`
- Grain: `one row per (msd_track_id, token)`

### Important Join Constraint

There is no native direct key between the current `FMA` audio dataset and the current `MSD` lyrics dataset. They should be treated as parallel teaching datasets unless you later build a crosswalk by matching title/artist pairs.

## Dataset A: `pachamix_audio_core.parquet`

### Purpose

- audio-feature exploration
- dimensionality reduction
- clustering
- content-based recommendation from structured audio descriptors

### Grain

One row per `FMA` track.

### Primary Key

- `track_id`

### Core Columns

| Column | Type | Description |
| --- | --- | --- |
| `track_id` | `Int64` | FMA track identifier |
| `title` | `String` | track title from FMA metadata |
| `genre_top` | `String` | top-level genre label from FMA, nullable |
| `artist_name` | `String` | artist name from FMA metadata |

### Audio Feature Columns

All remaining `518` columns are numeric `Float64` features derived from the FMA feature table.

Naming pattern:

- `<family>_<stat>_<component>`

Where:

- `<family>` is the feature family
- `<stat>` is one of `kurtosis`, `max`, `mean`, `median`, `min`, `skew`, `std`
- `<component>` is a numbered dimension such as `01`, `02`, ..., depending on the family

### Feature Families

| Family | Components | Stats per Component | Column Count | Notes |
| --- | --- | --- | --- | --- |
| `chroma_cens` | `12` | `7` | `84` | chroma from CENS representation |
| `chroma_cqt` | `12` | `7` | `84` | chroma from constant-Q transform |
| `chroma_stft` | `12` | `7` | `84` | chroma from STFT representation |
| `mfcc` | `20` | `7` | `140` | Mel-frequency cepstral coefficients |
| `rmse` | `1` | `7` | `7` | root mean square energy |
| `spectral_bandwidth` | `1` | `7` | `7` | spectral bandwidth summary |
| `spectral_centroid` | `1` | `7` | `7` | spectral centroid summary |
| `spectral_contrast` | `7` | `7` | `49` | spectral contrast bands |
| `spectral_rolloff` | `1` | `7` | `7` | spectral rolloff summary |
| `tonnetz` | `6` | `7` | `42` | tonal centroid features |
| `zcr` | `1` | `7` | `7` | zero-crossing rate summary |

### Example Columns

- `chroma_cens_mean_01`
- `mfcc_std_14`
- `spectral_contrast_median_03`
- `tonnetz_skew_06`
- `zcr_mean_01`

## Dataset B: `pachamix_lyrics_long.parquet`

### Purpose

- lyric exploration by title/artist/release
- text preprocessing under instructor control
- downstream bag-of-words, TF-IDF, or embedding generation
- metadata-aware lyric analysis

### Grain

One row per unique `(msd_track_id, token)` pair, with aggregated count.

### Keys

- logical key: `(msd_track_id, token)`

### Schema

| Column | Type | Description |
| --- | --- | --- |
| `msd_track_id` | `String` | MSD track identifier; joins to `songs.track_id` in `track_metadata.db` |
| `title` | `String` | track title from MSD metadata |
| `song_id` | `String` | Echo Nest / MSD song identifier |
| `release` | `String` | release / album name from MSD metadata |
| `artist_id` | `String` | Echo Nest / MSD artist identifier |
| `artist_mbid` | `String` | MusicBrainz artist identifier, nullable |
| `artist_name` | `String` | artist name from MSD metadata |
| `duration` | `Float64` | track duration in seconds from MSD metadata |
| `artist_familiarity` | `Float64` | Echo Nest familiarity score |
| `artist_hotttnesss` | `Float64` | Echo Nest hotttnesss score |
| `year` | `Int64` | release year, often `0` when unavailable |
| `track_7digitalid` | `Int64` | 7digital track identifier or sentinel value from MSD |
| `shs_perf` | `Int64` | SecondHandSongs performance identifier or sentinel value |
| `shs_work` | `Int64` | SecondHandSongs work / clique identifier or sentinel value |
| `token` | `String` | normalized lyric token from the official musiXmatch/MSD vocabulary |
| `count` | `Int64` | token frequency for that track |

### Notes

- This dataset does **not** contain verbatim raw lyrics.
- The official `musiXmatch/MSD` release provides only bag-of-words style token counts due copyright restrictions.
- If `track_metadata.db` is absent, the metadata columns above are omitted and the dataset contains only:
  - `msd_track_id`
  - `token`
  - `count`

## Optional Dataset C: `pachamix_playlists/playlist_events.parquet`

### Purpose

- collaborative filtering
- popularity baselines
- playlist continuation
- graph construction

### Grain

One row per unique `(playlist_id, track_uri, position)`.

### Important Source Note

`MPD` provides observed playlist order.

`Playlist2vec` official exports do **not** necessarily provide observed track order inside the playlist membership table.
When `position` is absent at ingestion time, the builder synthesizes a deterministic per-playlist `position` and marks that fact with:

- `position_observed = false`

This makes the dataset suitable for:

- collaborative filtering
- popularity baselines
- matrix factorization
- graph construction

It does **not** make the dataset a faithful sequential playlist source.

### Schema

| Column | Type | Description |
| --- | --- | --- |
| `playlist_id` | `String` or `Int64` | source-native playlist identifier; actual Playlist2vec exports use string ids, while MPD commonly uses integers |
| `playlist_name` | `String` | playlist name |
| `track_uri` | `String` | canonical song identifier in the playlist source |
| `track_name` | `String` | track title from the playlist source |
| `artist_name` | `String` | artist name from the playlist source |
| `album_name` | `String` | album name from the playlist source |
| `position` | `Int64` | track order in the playlist; may be synthesized deterministically if not observed in the source |
| `position_observed` | `Boolean` | `true` when order came from the source, `false` when position was synthesized during ingestion |

## Optional Dataset D: `pachamix_playlists/playlist_stats.parquet`

### Grain

One row per playlist.

### Schema

| Column | Type | Description |
| --- | --- | --- |
| `playlist_id` | `String` or `Int64` | source-native playlist identifier; actual Playlist2vec exports use string ids, while MPD commonly uses integers |

### Grain

One row per `track_uri`.

### Schema

| Column | Type | Description |
| --- | --- | --- |
| `track_uri` | `String` | song identifier in the playlist source |
| `playlist_count` | `UInt32`/`Int64` depending on Polars output | number of distinct playlists containing the song |

## Optional Dataset F: `pachamix_song_graph_edges.parquet`

### Purpose

- song co-occurrence graph analysis
- centrality
- PageRank

### Grain

One row per undirected song pair.

### Schema

| Column | Type | Description |
| --- | --- | --- |
| `src_track_uri` | `String` | first song URI in the co-occurrence pair |
| `dst_track_uri` | `String` | second song URI in the co-occurrence pair |
| `weight` | `UInt32`/`Int64` depending on Polars output | number of playlists where the pair co-occurs |

### Construction Rule

- self-loops are excluded
- pairs are canonicalized using `src_track_uri < dst_track_uri`
- `weight` is the co-occurrence count across playlists
